# 上市、上櫃官方個股行情資料

本資料管線與既有市場儀表板資料分開，避免擴大 `docs/data.json`，也避免個股行情更新失敗影響既有指數與期貨更新。

## 官方來源

| 市場 | 公司名單 | 每日行情 |
|---|---|---|
| 上市 | [TWSE 上市公司基本資料](https://openapi.twse.com.tw/v1/opendata/t187ap03_L) | [TWSE STOCK_DAY_ALL](https://openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL) |
| 上櫃 | [TPEx 上櫃公司基本資料](https://www.tpex.org.tw/openapi/v1/mopsfin_t187ap03_O) | [TPEx 每日收盤行情](https://www.tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes) |

公司名單用來限制個股範圍，避免把行情端點中的 ETF、權證或其他非公司證券直接當成普通公司股票。

## 輸出與歷史保存

- `docs/stocks.json`：上市與上櫃各自的**最新成功快照**，每次更新覆蓋該市場前一個快照。
- `stock_data.py`：獨立收集、正規化、驗證及原子寫入。
- `.github/workflows/update-stocks.yml`：台灣時間週一至週五 18:37、20:37 更新，亦可手動執行。
- Git commit 歷史可追溯過去曾提交的快照；但目前 JSON 本身**不是逐日歷史資料庫**，不提供逐日查詢結構。

每筆行情統一欄位：市場、股票代號、名稱、交易日期、開高低收、漲跌、成交股數、成交金額、成交筆數、資料來源。

## 資料品質與失敗規則

1. 兩個市場分開抓取、分開驗證；一個市場失敗不覆蓋另一市場的最後成功快照。
2. HTTP 成功不等於資料有效；必須是 JSON 陣列、公司名單有效、行情日期一致、有效股票筆數達最低門檻、代號不重複。
3. 個別股票 OHLC 缺漏、價格非正數或高低價關係異常時，跳過該列並計數；異常列比例超過 5% 才拒絕整個市場快照。
4. 有效筆數不得低於該市場上次成功快照的 80%，避免截斷回應被當成完整資料；市場規模變動時仍需人工檢視。
5. 官方 API 連線失敗會重試一次；更新失敗時保留舊行情，標記 `status=failed`、`checked_at`、`error` 及 `last_success_date`。
6. 若來源回傳日期早於已保存日期，拒絕覆蓋。
7. partial 狀態會在 GitHub Actions 輸出 warning；任何市場最後成功日期超過 4 個日曆日，workflow 會失敗，避免長期過期卻顯示綠燈。
8. JSON 使用緊湊格式，並以暫存檔原子替換，避免中途寫入造成檔案毀損。

## 資料時間與限制

兩個每日行情 API 是最新交易日快照，不提供完整歷史區間，也不是盤中即時報價。網站呈現時必須明確標示各市場交易日期及更新狀態。休市日以最後交易日快照為準；目前 4 日曆日門檻是保守的監控值，長假期間可能需要人工確認。

本階段不改動首頁版面，也不接入即時報價。真實 API smoke test 只印出 HTTP 狀態、筆數及欄位名稱，不寫入正式資料；此步驟不阻擋 PR，最終仍須以 GitHub Actions 實際排程結果確認 TPEx 可用性。
